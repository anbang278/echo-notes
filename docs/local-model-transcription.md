# 本地模型长音频转写

在设置 → 离线转写 → 转写服务，选择 **本地模型（OpenAI 兼容）**。

- Base URL 默认 `http://127.0.0.1:18080/v1`，可以填写本机 OpenAI 兼容转写服务的地址。
- 普通模型：`mlx-community/Qwen3-ASR-0.6B-8bit`。
- 分说话人模型：`local/qwen3-asr-0.6b-sortformer-4spk`，最多四位匿名说话人；也可填写服务支持的自定义模型 ID。
- API Key 可空；填写后使用独立的 Obsidian SecretStorage 槽位。
- 默认自动识别语言，也可选择中文、英文或填写语言代码。

地址、模型、语言按服务商分别保存。升级时保留当前配置，切换服务商后恢复各自配置；原 LM Studio 入口继续沿用原行为。本入口仅支持桌面 Obsidian、本地文件系统 Vault 和本机回环地址，不支持局域网或远端域名。

## 长录音与任务恢复

本入口没有 25MiB 客户端上限。标准 OpenAI 兼容服务使用流式 multipart 上传，每次读盘不超过 4MiB；服务端容量限制按实际响应显示。连接最长等待 10 秒，上传连续 60 秒无进展会中止连接；上传结束后可等待服务推理最多 12 小时。

设置中的自检只检查字段。开始转写时，插件才探测当前本机 MLX 服务；核验协议、实例和模型能力后，使用可恢复任务通道。该服务支持单文件 1GiB、实际解码时长 8 小时，上传块属于同一个转写任务。

任务中心显示上传、解码、说话人分离、转写、对齐和保存阶段。网络断开或插件重载后，可继续原任务；源文件、配置及服务实例须一致。服务重启或任务过期时需要重新上传。标准接口只有上传和等待阶段，没有断点续传协议；停止连接后会提示结果未知，不自动重复提交。

本地 MLX 任务可取消；服务确认前显示“正在取消”。转写稿保存成功后才清理服务端结果。写稿失败可以重新取回结果，清理失败不影响已经保存的稿件。

## 验收与服务部署

本地 MLX 服务源码和控制台位于 `integrations/local-mlx-asr/`。测试在独立 18081 实例进行；服务包、控制台和插件安装均需要通过当前 Trellis 任务的实际验收门禁。完整交付后，在 Develop-obsidian 点击“重新加载第三方插件”即可使用新测试版本；若插件已关闭，再打开 Echo Notes。

模型按音频窗口分段处理同一条录音，完成后保存完整转写稿，无需手动切文件。本次面向最长约 3 小时的会议：已完成 26 分钟公开自然会议的普通与分离模式验证，并以低负载测试检查 3 小时分段覆盖和短尾处理。按用户要求停止额外长时压力测试，未做完整 3 小时真实推理验收。

长音频转写成功只证明完整工程链路；文字准确性与说话人质量仍需结合录音内容核对。
