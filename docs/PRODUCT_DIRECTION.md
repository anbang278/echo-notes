# Echo Notes 产品方向

## 产品目标

Echo Notes 要成为 Obsidian-native 的 Personal AI Memory Layer。它从真实发生的录音、会议和思考开始，把内容逐步沉淀为可搜索、可关联、可复盘、可被 Personal Agent 使用且能追溯到原文的个人上下文。

主链路是：

> 音频或语音输入 → 可靠转写 → 场景化分析 → 带原文证据的候选记忆 → 人工确认或修正 → 人物、项目、组织、决策、任务和经验 → 跨记录聚合 → Personal Agent 上下文

## 产品原则

1. 原始录音、完整转写稿和用户人工编辑是真源，AI 输出只能作为可重建的派生结果。
2. 重要数据优先使用 Vault 内的 Markdown、frontmatter、WikiLink 和可读 JSON，避免只能由插件解释的封闭状态。
3. 每条长期记忆必须有稳定 ID、来源、证据、时间、状态、模型和模板版本等审计信息。
4. 高影响记忆进入长期画像前应经过候选、确认、修正或拒绝流程。
5. 可靠性、失败恢复和内容保护优先于新增 Provider 或高级检索基础设施。
6. 外部请求必须由用户明确配置和触发，不重复产生可能收费的请求。

## 0.4.1 真实状态

- 录音与转写：实时 AgentPlan 和多个离线 Provider 已可生成受托管区块保护的 transcript；阿里百炼、SiliconFlow 和 MOSI 的长音频成功分段可通过 transcript 检查点跨失败与重启复用。
- AI 分析：支持模板、长文本分块、最终汇总、frontmatter 生命周期和人工内容保护；成功分块按模板隔离保存在 transcript 检查点中，失败或重启后可复用严格匹配的连续前缀。
- Echo Memory：可从 transcript 与成功分析提取带证据的候选包；长文本成功分块在 Vault 共享检查点中按 transcript 隔离，失败或重启后只补齐严格匹配的剩余分块；最终生成会议页和默认待审核的 `.review.md` sidecar，并可在 Obsidian 内逐条批准、修正、拒绝或重置。
- 长期画像：只消费已批准断言；用户可确认同主体断言之间的冲突、补充、替代或作废关系。替代/作废目标可从画像撤下，撤销关系或审核值变化后可重建恢复；候选、审核与关系历史均保留。
- 任务中心：持久化最多 100 条安全任务摘要、重启中断状态和恢复上下文；整段请求和不支持分块的 Provider 仍会完整重试。
- 当前 Memory 状态：单主体画像、项目/人物/时间线跨记录视图和可预览上下文包均可从候选、审核与关系真源重建；上下文包支持明确范围和长度预算，但尚未接入语义检索或外部 Agent 执行动作。

## 当前阶段边界

近期不引入向量数据库、复杂聊天界面、外部 Agent 自动执行或更多同质 Provider。只有在可靠转写、候选审核和跨记录证据链稳定后，才评估这些能力。
