# 三个信息架构方向

均包含小月历、每日列表、标签/项目、问题材料和 Agent 连接。当前为提案，差别在主工作区组织。

## A 日历索引与原生笔记

```text
会议中心                       Obsidian 原生笔记区
┌────────────┬──────────────┐   ┌──────────────────┐
│ 小月历      │ 11 月 7 日    │   │ 会议标题与人工补充 │
│ 项目/标签   │ 会议摘要列表  │ → │ 录音/转写/项目入口 │
│ 日期待补全  │ 分阶段状态    │   │ Memory 管理区      │
└────────────┴──────────────┘   └──────────────────┘
```

推荐该方向，延续 Markdown 使用习惯，自定义详情组件较少。会议中心负责查找，详情在原生笔记打开，项目页保留人工背景和受管时间线，问题材料为独立工作区。代价是详情与列表在不同叶子，窄屏依靠返回恢复范围。

## B 日期阅读器与内嵌详情

```text
┌───────────────────────────────────────────┐
│ 日期范围  小月历弹层  项目/标签  今天       │
├──────────────────┬────────────────────────┤
│ 当天会议与摘要    │ 选中会议详情            │
│ 处理状态          │ 原文/项目/分析/记忆入口   │
├──────────────────┴────────────────────────┤
│ 整理问题材料 → 选材 → 核验 → 导出          │
└───────────────────────────────────────────┘
```

适合连续阅读当天多场会议，在同一工作区切换详情，仍可打开原生笔记。窄屏列表→详情二级导航。代价是内嵌详情与文档一致性、滚动和返回状态需额外维护。

## C 项目工作台与讨论时间线

```text
┌────────────┬─────────────────────────────┐
│ 项目导航   │ 项目背景与近期讨论          │
│ 全部会议   │ 小月历/每日列表/标签筛选     │
│ 未关联项目 │ 按日期的会议摘要时间线      │
│ 日期待补全 │ 整理问题材料与已保存问题    │
└────────────┴─────────────────────────────┘
```

适合按项目追溯长期决策，直接进入已保存问题。原文在原生笔记打开，Agent/迁移是独立维护入口。代价是无项目会议需要显眼入口，日常按日期浏览多一步切换。
